## Same GKI ABI, different module-signing key

This build compiled //common:kernel_x86_64 again (an action-cache miss; the cause was not investigated), and Kleaf
generates a new random module-signing key each time it does. So its bzImage differs, but every ABI file is
byte-identical to the ANAL-171 dist:
  identical  vmlinux.symvers
  identical  kernel_x86_64_Module.symvers
  identical  System.map
  identical  abi_symbollist
  identical  dot_config
  identical  modules.builtin

  bzImage sha256: anybook-amd 6d964789134e6fc4…  anybook-vdev d92572c9a232138d…
  GKI module sig_key (virtio_blk.ko): anybook-amd 4A:60:D6:F6:14:73:08:B7:2D:82:E5:59:BE:17:2C:49:F6:4A:30:4F
                                      anybook-vdev 76:EE:F3:B7:3B:45:EF:AF:51:B6:C8:92:47:F1:6C:40:84:46:F5:A4

Consequence: boot the ANAL-171 bzImage with the ANAL-171 GKI modules only (kernel-cf-modset.py takes them from that
dist's system_dlkm staging archive). The board build contributes only its unsigned vendor modules. Their vermagic is
the same (`6.18.21-android17-5-g44a90255c95f SMP preempt mod_unload modversions`) and their CRCs match vmlinux.symvers.
