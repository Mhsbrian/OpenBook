Source (frameworks/base 8f5dedd3edc3 + OpenBook patches):
- ComputerControlSession's lifecycle callback unregisters its accessibility display proxy in onBlocked() and
  registers it again in onActive().
- ProxyAccessibilityServiceConnection.getWindows() calls super.getWindows(), which returns null when the connection
  may not retrieve windows (hasRightsToCurrentUserLocked / canRetrieveWindowsLocked / checkAccessibilityAccess), and
  dereferences it without a check.
HYPOTHESIS: the re-registered connection lacks the window-retrieval capability or installed-service info the first
registration got. Not yet fixed: Quire ends the run with "After the pause, the system stopped showing Quire what's
in Settings, so the run ended" and closes the session. Q6 needs the platform fix before an agent continues after a
pause.
